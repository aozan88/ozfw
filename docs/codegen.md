# OzFw kod üretici

`Frameworks/OzFw/OzFw.CodeGenerator/OzFw.ScribanCodeGen` bir veri modelini (JSON, CSV, DBML ya da Mermaid) okur,
doğrular ve iki şey üretir:

- **SQL DDL** (PostgreSQL). Migration kullanılmaz: script review edilip DB'ye elle uygulanır.
- **C# katmanları**: entity, EF eşlemesi, DTO, repository, servis, validation, controller, DI kayıtları ve
  ilk çalıştırmada modülün projeleri (API/Application/Data). Ortak/Sistem modülleriyle aynı düzen.

Örnek: `samples/codegen/ornek.*` modelinden üretilmiş `Projects/backend/USBS/USBS.Services/Ornek` modülü ve `sql/ornek/`.

## Çalıştırma

Repo kökünden:

```bash
dotnet run --project Frameworks/OzFw/OzFw.CodeGenerator/OzFw.ScribanCodeGen -- --model samples/codegen/ornek.dbml --dry-run
```

| Seçenek | Açıklama |
|---|---|
| `--model <dosya>` | `.json` (ara model), `.csv`, `.dbml` (dbdiagram.io), `.mmd` / `.mermaid` (erDiagram) |
| `--root <klasör>` | Repo kökü (varsayılan: geçerli klasör). SQL `<root>/sql/<modul>/`, C# `<root>/Projects/backend/<NamespaceRoot>/...` |
| `--only sql,code` | Üretilecek hedefler. Varsayılan: hepsi |
| `--dry-run` | Hiçbir dosya yazmaz, ne yazılacağını listeler |
| `--force` | `<auto-generated>` başlığı olmayan (elle düzenlenmiş) üretim dosyalarının da üzerine yazar |
| `--api-port <port>` | Yeni modülün HTTPS portu (HTTP = port+1). Varsayılan: 24300 |
| `--no-sln` | Yeni projeleri sln'e eklemez |
| `--module`, `--schema`, `--namespace` | Model dosyasındaki değerleri geçersiz kılar |
| `--export-model <dosya.json>` | Normalize edilmiş modeli JSON olarak yazar (diyagram/CSV → ara model) |

Satır durumları: `yeni`, `güncellendi`, `değişmedi`, `korundu` (scaffold dosyası zaten var, dokunulmadı),
`atlandı` (üretim dosyası elle düzenlenmiş görünüyor; `--force` olmadan yazılmaz).

Çıkış kodları: `0` başarılı, `1` model okunamadı ya da doğrulanamadı (tüm hatalar listelenir), `2` hatalı kullanım.
Argümansız çalıştırılırsa eski (sabit listeli) şablon akışı çalışır.

## Girdi formatları

Aynı modelin dört formatı `samples/codegen/` altında; dördü de birebir aynı ara modeli ve DDL'i üretir (testle doğrulanır).

- **JSON**: ara modelin kendisi, şema `docs/codegen-model.schema.json`.
- **CSV**: her satır bir alan. Başlık `entity,field,type,nullable,length,precision,scale,fk_target,description`
  (isteğe bağlı `column`, `dto_name`, `on_delete`). Ayraç `,` ya da `;` (Excel TR). Modül `# module: Ornek` satırıyla verilir.
- **DBML**: `Table şema.tablo { ... }`, kolon ayarları (`not null`, `note`, `ref: > t.id`), `Ref:` satırları
  (`[delete: cascade]`), `Enum` blokları. DBML'de kolonlar varsayılan olarak nullable'dır. `indexes` blokları şimdilik atlanır.
- **Mermaid erDiagram**: `tip ad [PK|FK] "yorum"`. Alanlar varsayılan olarak zorunludur. Yorumda `;` ile ayrılmış
  yönergeler: `nullable`, `maxLength: 100`, `precision: 18,2`, `ref: Hedef`, `onDelete: cascade`, kalan metin açıklamadır.
  FK'nin zorunluluğu kardinaliteden gelir (`||` zorunlu, `|o` isteğe bağlı). İlişki etiketi FK kolonunun adı olabilir.

Diyagram ve CSV'de `snake_case` / `UPPER` adlar PascalCase'e çevrilir (`ust_kategori_id` → `UstKategoriId`).
BaseEntity kolonları (`id`, `olusturulma_tarihi` ...) yazılabilir, okuyucu bunları atlar. İlişkiler yalnızca
hedefin `id` kolonuna olabilir; çoka-çok ilişki için ara entity tanımlanmalıdır.

## Üretilen DDL

- `sql/<modul>/_all.sql`: şema + tüm tablolar, FK bağımlılık sırasıyla (önce referans verilenler).
- `sql/<modul>/<tablo>.sql`: tek tablo; referans verdiği tablolar önceden var olmalı.
- Her tabloda BaseEntity kolonları, `pk_<tablo>`, FK constraint'leri (`fk_<tablo>_<kolon>`) ve FK index'leri
  (`ix_<tablo>_<kolon>`); açıklamalar `COMMENT ON` olarak yazılır.
- Script idempotenttir (`IF NOT EXISTS`); döngüsel FK'ler tablolardan sonra `DO $$ ... duplicate_object` bloklarıyla eklenir.
- `DateTime` → `timestamp` (DbContext'lerde `Npgsql.EnableLegacyTimestampBehavior` açık), enum → `integer`.

## Üretilen C# kodu

İki tür dosya vardır:

- **`*.g.cs`** (`// <auto-generated>` başlıklı): her çalıştırmada yeniden üretilir, elle düzenlenmez.
  Hepsi `partial`; özelleştirme aynı sınıfın `.g.cs` olmayan ayrı bir dosyasında yapılır.
- **Scaffold**: yalnızca yoksa oluşturulur, sonra size aittir — servis constructor'ı (`<E>Servis.cs`), `<M>DbContext.cs`,
  `MapsterConfig.cs`, üç csproj, `Program.cs`, `Extensions/<M>ApiProject.cs`, `launchSettings.json`, appsettings dosyaları.

Entity başına (`<M>` modül, `<E>` entity):

| Dosya | İçerik |
|---|---|
| `USBS.Common.Domain/<M>Entities/<E>.g.cs` | PascalCase alanlar, referans navigation'lar, `dtoName` için `[DtoField]` |
| `USBS.Common.Dtos/<M>Dtos/<E>Dto.g.cs` | DTO (enum'lar `int`) |
| `USBS.<M>.Data/Persistence/Configurations/<E>Configuration.g.cs` | Tablo/kolon adı ve tipi, PK/FK/index adları DDL ile aynı; `ConfigurePartial` kancası |
| `USBS.<M>.Data/Repositories/<E>Repository.g.cs`, `Application/Contract/I<E>Repository.g.cs` | `GenericRepository<E>` |
| `Application/Business/I<E>Servis.g.cs`, `<E>Servis.g.cs` | `BaseService<E, EDto>` (CRUD hazır; iş kuralları override ile) |
| `Application/Validations/<E>DtoValidation.g.cs` | Modelden kurallar (zorunlu, uzunluk, precision, zorunlu FK); `EkKurallar()` kancası |
| `USBS.<M>.API/Controllers/<E>Controller.g.cs` | `BaseController` — 8 POST uç |

Modül başına: `<M>DbContext.g.cs` (DbSet'ler), `BaseEntityColumns.g.cs`, `<M>DataRegistration.g.cs`
(`AddOrnekData`), `<M>ApplicationRegistration.g.cs` (`AddOrnekApplication`: servisler ve validator'lar),
`GeneratedMappings.g.cs` (yalnızca `dtoName` farkları; diğer alanları Mapster ada göre eşler).

İlk çalıştırmada yeni csproj'lar `USBS.sln` içinde mevcut `Services` klasörünün altına `<M>` klasörüyle eklenir
(yalnızca Debug/Release | Any CPU; diğer projelere dokunulmaz). Yeni API kendi profiliyle çalışır:
`dotnet run --launch-profile <M>.API-Development` (bağlantı dizesi `appsettings.Development.json`'da, şifresiz şablon).

Tutarlılık testleri (`USBS.Tests/CodeGen`): dört formatın aynı modeli vermesi, EF'in `GenerateCreateScript()` çıktısı
ile DDL'in kolon/tip/null/PK/FK/index bazında aynı olması, repo'daki üretilmiş dosyaların modelle güncel olması.

Şimdilik desteklenmeyenler: `Geometry` alanlar C# tarafında (yalnızca `--only sql`), ters (koleksiyon) navigation'lar
(`ConfigurePartial` içinde eklenebilir), DBML `indexes`/`unique`, çoka-çok ilişkiler (ara entity ile).
